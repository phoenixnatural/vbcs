## 2. Functional scope (what the system does)

1. **Detect** employees **Exiting** (`PER_PERIODS_OF_SERVICE.actual_termination_date` in a −15..+15 day window) and **Moving** (ORG_ID or cost-allocation SEGMENT3 change, +1..+15 days).
2. **Notify** the Reporting Manager (RM) via FYI workflow at intervals — Exit: `DAY_15/DAY_10/DAY_5/LAST_DAY`; Movement: `DAY_1/5/10/15_AFTER`. CC DOA Superuser group on Exit DAY_5 / Movement DAY_10_AFTER.
3. RM provides a **replacement** via a form. None by cut-off → **auto-default to the RM** (FALLBACK). Exit cut-off = last working day; Movement cut-off = effective_date + 16 (propagation Day 17).
4. **Propagate** the replacement to open **PR** (`po_requisition_lines_all.to_person_id`), **PO** (distributions `deliver_to_person_id` STANDARD / header `agent_id` BLANKET), **QP** approver mappings, and **reassign** open WF notifications (`WF_NOTIFICATION.TRANSFER`).
5. **DOA Superuser** override form (EXIT only, within 15-day window).
6. **Manager** + **Superuser** replacement **reports** (pipe-delimited TEXT CPs).
7. **BCP/DR switch** (`ON`/`FUSION_ONLY`/`OFF`) and **staggered OU enablement** (per-ORG_ID enable list).

### 5.2 HARD CONSTRAINTS (each cost a failed round — do not regress)
1. **`frmxml2f` CANNOT rebuild EBS-template / APPSTAND object-group subclassing.** It dies `ERROR - an exception has been encountered: null` (swallowed Jdapi NPE). Proven: pristine `TEMPLATE_fmb.xml` itself fails. ⇒ **standalone forms only**.
2. The build only succeeded after stripping, in order: `Automatic*` LOV attrs → `Parent*` attrs → `ObjectGroup`/`ObjectGroupChild` lines → all `SubclassObjectGroup="true"` furniture (CALENDAR block, PROGRESS_INDICATOR, TOOLBAR/STANDARD_DAYS_LABELS/ARABIC_DAYS_LABELS canvases, POPUP/POPUP_FOLDER menus).
3. **Every displayed `<Item>` needs an explicit `Height`** (e.g. `Height="250"`) or it renders zero-height (invisible). The converter does not default it.
4. **Record groups for LOVs MUST be runtime-created**, NOT design-time static populated. A `Static` RG cannot be filled by `POPULATE_GROUP_WITH_QUERY` (silent runtime failure → empty LOV that just beeps). Correct pattern, in **KEY-LISTVAL**: `CREATE_GROUP_FROM_QUERY('RT_x', '<sql>') → POPULATE_GROUP(rg) → SET_LOV_PROPERTY('<LOV>', GROUP_NAME, 'RT_x')`. Static RGs remain in the XML only to satisfy the compiler/LOV column mapping. Queries are built by **string concatenation** of `:BLOCK.LOGGED_PERSON_ID` (not `:item` binds).
5. **Color attributes `BackgroundColor`/`ForegroundColor` are NOT valid on `<Item>`** (schema XML-24535 reject). Inline item color does not work this way. Standard EBS colors come from APPSTAND **visual attributes** `FLEX_EDITABLE/FLEX_REQUIRED/FLEX_NOT_EDITABLE` which are `SubclassObjectGroup="true"` — i.e. the very subclassing that NPEs. (A LOCAL non-subclassed `<VisualAttribute>` referenced via `VisualAttributeName` is the untested headless-safe option — see §9.)
6. Restricted bastion shell rejects heredocs/multi-line paste (`Multiline input command must end with a new line character`). Build files one `echo '…' >>` per line, or `vi` a script then `sh` it. Long sed/edits: put in a `.sed`/`.sh` file and transfer the FILE (don't retype — long lines must not wrap).
7. Never hand the user a literal `<pwd>`/placeholder inside a command — shell parses `<pwd` as redirection (`ORA-01017` / `pwd: No such file`). Tell them to replace including angle brackets. (Bit us twice — `CHANGEME` left unreplaced → ORA-01017.)
